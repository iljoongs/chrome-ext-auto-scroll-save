# 자동 스크롤 후 페이지 저장

지연 로딩(lazy loading) 이미지가 있는 페이지도 빠짐없이 저장할 수 있도록,
확장 프로그램 아이콘을 한 번 클릭하면 페이지를 끝까지 자동으로 스크롤해
이미지를 모두 불러온 뒤 **HTML 파일 + 리소스 폴더** 형태로 저장하는 크롬
확장 프로그램(Manifest V3)입니다.

## 설치 방법 (개발자 모드)

1. 크롬 주소창에 `chrome://extensions`를 입력해 이동합니다.
2. 우측 상단의 "개발자 모드" 토글을 켭니다.
3. "압축해제된 확장 프로그램을 로드합니다" 버튼을 클릭합니다.
4. 이 저장소 폴더(`manifest.json`이 있는 폴더)를 선택합니다.

## (필수) 사전 설정: 크롬 기본 다운로드 위치를 `E:\Temp`로 변경

이 확장 프로그램은 저장 위치를 고르는 대화상자 없이, **크롬의 현재 기본
다운로드 폴더**에 항상 저장합니다. HTML 파일과 리소스 폴더가 항상 같은
위치에 함께 저장되도록 하려면, 크롬 설정에서 기본 다운로드 위치를
`E:\Temp`로 한 번만 변경해 두어야 합니다.

1. `chrome://settings/downloads`로 이동합니다.
2. "위치"(저장 위치) 항목을 `E:\Temp`로 변경합니다. (`E:\Temp` 폴더가
   없다면 먼저 만들어 두세요.)
3. "다운로드 전에 각 파일이 저장될 위치 확인" 옵션은 꺼져 있어야 합니다
   (켜져 있으면 리소스 파일마다 저장 위치를 묻는 대화상자가 뜹니다).

> 크롬 확장 프로그램 API는 다운로드 경로로 절대 경로를 지정할 수 없고,
> 항상 "현재 기본 다운로드 폴더" 기준 상대 경로만 허용합니다. 확장
> 프로그램이 그 기본 폴더 자체를 바꿀 수는 없기 때문에, 위 설정을 한 번
> 해 두는 것이 유일한 방법입니다.

## 사용 방법

1. 저장하려는 페이지(회차)를 엽니다.
2. 툴바에서 이 확장 프로그램 아이콘을 클릭하면 작은 창이 열립니다.
   - **제목**: 저장할 작품 제목을 입력합니다(예: `광마회귀`). 페이지 제목이
     숫자로 시작하는 경우(예: `55화 - 늑대닷컴`) 이 제목을 앞에 붙여
     `광마회귀 55화 - 늑대닷컴`으로 저장합니다. 숫자로 시작하지 않는
     제목이거나 비워두면 페이지 제목 그대로 저장합니다.
   - **모드**: `현재 화만 저장` 또는 `연속 저장`(다음화가 없을 때까지)을
     고릅니다. 마지막 입력/선택은 기억됩니다.
   - **시작**을 누릅니다.
3. 아이콘 배지에 현재까지 저장한 화 수(1, 2, 3, ...)가 표시되며, 각 화마다
   페이지가 끝까지 자동으로 스크롤되고 이미지들이 로드될 때까지 기다린
   뒤 저장합니다.
4. **연속 저장 모드에서는 저장이 끝나면 자동으로 "다음화"로 넘어가서 같은
   과정을 반복합니다.** "다음화" 버튼이 없어지는(비활성화된) 마지막 화까지
   계속 진행됩니다. **진행 중에 아이콘을 누르면 나오는 "중단" 버튼**으로
   멈출 수 있습니다 (지금 저장 중인 화는 끝까지 마치고, 그다음 화로 넘어가기
   전에 멈춥니다). `현재 화만 저장` 모드는 한 화만 저장하고 바로 끝납니다.
5. 모든 화가 끝나면(또는 실패하면) 배지가 사라집니다(성공) 또는 "X"가
   표시됩니다(실패, 그 시점에서 전체 진행이 멈춤). 자세한 내용은
   확장 프로그램의 서비스 워커 콘솔 로그를 참고하세요.
6. 저장이 진행되는 동안 브라우저 상단에 **"'자동 스크롤 후 페이지
   저장'이(가) 이 브라우저를 디버깅하고 있습니다"** 라는 배너가 나타날 수
   있습니다. 핫링크 방지(다른 사이트에서 직접 링크로 접근 시 이미지를
   차단하는 것)가 걸린 이미지까지 정상적으로 받아오기 위해 크롬 개발자
   도구 프로토콜을 잠깐 사용하는 것으로, 정상 동작이며 저장이 끝나면
   자동으로 사라집니다. (참고: 이미 그 탭에서 개발자 도구를 직접 열어둔
   상태라면 이 기능이 연결되지 않을 수 있는데, 이 경우 핫링크 방지가
   없는 리소스는 평소처럼 저장되고 핫링크 방지가 걸린 리소스만 실패할
   수 있습니다.)

저장 결과물은 `E:\Temp\<페이지 제목>.html`과
`E:\Temp\<페이지 제목>_files\` 폴더입니다. 이 둘을 항상 같은 위치에
함께 두어야 HTML 파일을 열었을 때 이미지 등 리소스가 정상적으로
보입니다.

## 스크롤 간격 / 대기 시간 조정

`background.js` 상단의 상수 값을 수정해서 조정할 수 있습니다.

- `SCROLL_STEP_PX` (기본 500): 한 번에 스크롤하는 픽셀 수
- `SCROLL_INTERVAL_MS` (기본 350): 스크롤 간 대기 시간(ms)
- `IMAGE_WAIT_INTERVAL_MS` (기본 300): 이미지 로딩 상태를 확인하는 폴링 간격(ms)
- `IMAGE_WAIT_MAX_MS` (기본 8000): 이미지 로딩을 기다리는 최대 시간(ms)
- `POST_SCROLL_WAIT_MS` (기본 10000 = 10초): 스크롤과 이미지 로딩 대기가
  끝난 뒤, 저장을 시작하기 전에 한 번 더 고정으로 기다리는 시간(ms).
  스크롤에 반응해서 추가 콘텐츠를 불러오는 페이지에 여유를 주기 위함
- `MAX_SCROLL_ITERATIONS` (기본 400): 무한 스크롤 페이지에서 스크롤이
  끝없이 계속되는 것을 막는 안전장치(최대 반복 횟수)

## 알려진 제약 사항

- **일부 리소스 다운로드 실패**: 리소스는 `chrome.downloads.download`에
  원본 URL을 직접 넘겨 받아오므로(CORS 제약 없음), 대부분의 이미지는
  문제없이 저장됩니다. 다만 네트워크 오류, 로그인이 필요한 리소스,
  사이트의 다운로드 차단 정책 등으로 일부 리소스는 여전히 실패할 수
  있습니다. 이 경우 전체 저장 과정은 중단되지 않고, 해당 리소스만 HTML
  안에서 원본 URL을 그대로 유지합니다(로컬 경로로 치환하지 않음).
- **외부 스타일시트 내부까지는 완전히 재작성하지 않음**: `<link
  rel="stylesheet">`로 연결된 별도 CSS 파일은 파일 자체를 다운로드하고,
  그 안에서 참조하는 이미지 등도 함께 리소스로 받아오지만, CSS 파일
  내용 자체의 `url(...)` 경로를 로컬 경로로 바꿔치기하지는 않습니다
  (1차 버전 범위 밖). 인라인 `style` 속성과 `<style>` 태그 내용은
  로컬 경로로 재작성됩니다.
- **CSP 등 보안 정책**: 일부 사이트는 콘텐츠 보안 정책으로 스크립트
  실행이 제한되어 있어 자동 스크롤/캡처가 정상 동작하지 않을 수
  있습니다.
- 이 방식은 크롬의 실제 "웹페이지, 전체" 저장 기능과 완전히 동일하지는
  않은 근사치입니다 (예: `<script>` 파일은 기본적으로 리소스 수집
  대상에서 제외됩니다).

## 파일 구성

```
manifest.json        Manifest V3 설정
background.js        전체 흐름 오케스트레이션 (스크롤 → 캡처 → 다운로드 → 다음화)
popup.html/popup.js  아이콘 클릭 시 열리는 창 (제목 입력, 1장/연속 선택, 중단)
content-capture.js    페이지 컨텍스트에서 리소스 수집 + HTML 재작성
README.md             이 문서
```
